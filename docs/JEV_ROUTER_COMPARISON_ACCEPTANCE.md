首轮发现 3 项阻塞或重要问题，均通过新增回归复现后修复：

## 基线 embedding 一致性

使用原客户端 `OllamaEmbeddingClient` 和仓库指定 `qwen3-embedding:0.6b`，输出 1024 维，服务上下文设置 8192。保留 V2_goal_recent / C_bare_w10 配方、空动作零向量和 PCA/分类器权重、原权重阈值。

`router/embed.py` 说明：离线存 Ollama 原向量，在线客户端再次 L2 归一化；Ollama 本身输出单位向量，因此原项目视两者等价。本次不改变这个处理。

官方模型 blob 的 SHA256 为 `06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439`，下载后校验。历史训练时实际 GGUF/运行时哈希不在现有权重文件中，不能声称历史运行时逐位一致。此次固定 Ollama 0.11.11，记录安装指纹和实际服务元数据。

## 自动执行顺序

1. CPU 作业准备用户目录中的 Ollama 及 embedding 模型，不占 GPU。
2. 服务器运行评审修复后的回归与静态检查。
3. 两者成功后 GPU 作业加载 Jev 和 embedding；LLM/SLM 使用已确认端点。
4. 预热、验证 embedding 1024 维、核对服务模型名。
5. 099174d_1 四组技术验收，任务失败允许，计数或审计无效则停止。
6. 验收通过后交错运行 80 格，逐格保存结果、报告和日志，保留失败，不自动补跑。

GPU 最长 4 小时 30 分钟，单任务子进程最长 15 分钟。结束或异常只关闭本次启动的 Jev/Ollama；不取消、不修改原 SLM 作业 284851。共享模型服务的其他负载仍可能影响速度和数值复现，20 任务结果只用于开发比较。
