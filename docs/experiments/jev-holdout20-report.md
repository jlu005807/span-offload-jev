# Jev Holdout 20 任务对照实验报告

**实验运行：** Slurm 作业 `564370`；**结果目录：** `runs/jev-holdout20-564370/comparison/`；**配置：** `experiment_profile=holdout`，六组各跑同一批 20 个任务，共 120 个正式运行单元。

## 摘要

本轮结果不能得出“Jev 比原生 LLM 更好”的结论。Jev 0.75 与原生 LLM 都成功 19/20（95%），但平均端到端任务耗时更高；按用户给定的 Qwen 价格，Jev 0.75 的 Qwen 执行模型费用略低于原生组，不过 Jev 自身费用尚未计入。Jev 各阈值组在这批任务上都比原有路由器成功率高、平均时延低。阈值越高，SLM 卸载率总体越低、成功率总体越高。

本报告中的“成本”以 token 用量作为可比的资源消耗代理。实验报告未配置价格表（`fee_model=null`、`cost=null`），因此不能声称美元成本或精确费用；且不同模型 tokenizer 不同，跨模型 token 总量只适合作为粗略代理。

## Token 用量与成本代理

“执行输入/输出”统计路由到 LLM、SLM 的 Agent 执行请求；Jev 输入只计已知输入 token，符合本实验只记录 Jev 输入 token 的口径；原有路由器另使用 embedding，表中单独列出其已知 embedding 输入 token。`合计已知输入` = 执行输入 + Jev 输入 + embedding 输入；`执行输出` 单列，不把 Jev 的输出选项重复计为生成成本。

| 组别 | 执行输入 token | 执行输出 token | Jev 输入 token | Embedding 输入 token | 合计已知输入 token | 执行总 token（含输出） |
|---|---:|---:|---:|---:|---:|---:|
| Native LLM | 3,480,327 | 90,813 | 0 | 0 | 3,480,327 | 3,571,140 |
| Original router | 3,830,115 | 78,611 | 0 | 559,638 | 4,389,753 | 4,468,364 |
| Jev 0.50 | 2,967,318 | 91,081 | 726,784 | 0 | 3,694,102 | 3,785,183 |
| Jev 0.65 | 3,354,630 | 94,279 | 702,103 | 0 | 4,056,733 | 4,151,012 |
| Jev 0.70 | 3,168,045 | 89,911 | 630,619 | 0 | 3,798,664 | 3,888,575 |
| Jev 0.75 | 3,417,620 | 94,730 | 662,381 | 0 | 4,080,001 | 4,174,731 |

相对原生 LLM 的合计已知输入 token 变化：

- **Original router：** +26.1%（4,389,753 vs 3,480,327）。
- **Jev 0.50：** +6.1%（3,694,102 vs 3,480,327）。
- **Jev 0.65：** +16.6%（4,056,733 vs 3,480,327）。
- **Jev 0.70：** +9.1%（3,798,664 vs 3,480,327）。
- **Jev 0.75：** +17.2%（4,080,001 vs 3,480,327）。

注意：Jev 多次路由调用会带来额外输入 token。比如 Jev 0.75 执行请求输入 token 比原生组少，但加上 662,381 个 Jev 输入 token 后，合计已知输入反而略高于原生组。Jev 0.50 的 SLM 使用更多，但其执行输入总量仍低于原生组；实际货币费用取决于部署方式、模型价格及 GPU 占用，当前日志没有这些价格信息。

## 按给定 Qwen 价格估算的执行模型费用

采用你提供的价格，假设大模型是 Qwen3.8-27B（输入 `$0.35` / 百万 token，输出 `$2.55` / 百万 token），小模型是 Qwen3.5-9B（输入 `$0.10` / 百万 token，输出 `$0.15` / 百万 token）。计算公式为：

`Qwen费用 = 大模型输入token × 0.35 / 1,000,000 + 大模型输出token × 2.55 / 1,000,000 + 小模型输入token × 0.10 / 1,000,000 + 小模型输出token × 0.15 / 1,000,000`

| 组别 | Qwen 大模型费用 | Qwen 小模型费用 | Qwen 执行模型费用/20任务 | 每任务均值 | 每个成功任务均摊 |
|---|---:|---:|---:|---:|---:|
| Native LLM | $1.4497 | $0.0000 | **$1.4497** | $0.0725 | $0.0763 |
| Original router | $0.2553 | $0.3294 | **$0.5847** | $0.0292 | $0.0585 |
| Jev 0.50 | $0.5869 | $0.1754 | **$0.7623** | $0.0381 | $0.0586 |
| Jev 0.65 | $1.1683 | $0.0626 | **$1.2309** | $0.0615 | $0.0769 |
| Jev 0.70 | $1.2197 | $0.0296 | **$1.2493** | $0.0625 | $0.0694 |
| Jev 0.75 | $1.3764 | $0.0153 | **$1.3916** | $0.0696 | $0.0732 |

上表是 **20 个任务的 Qwen 执行模型 API token 费用估算**，不是完整系统费用。按此估算，Jev 0.75 的 Qwen 执行模型费用比原生组低约 **4.0%（$0.0580/20任务）**；Jev 0.70 低约 13.8%，Jev 0.65 低约 15.1%。这些差额尚未减去/加上 Jev 路由器本身的费用，也未计入 embedding 服务费用、GPU 时长或其他基础设施费用。

|---|---:|---:|---:|
| Jev 0.50 | 726,784 | 36,339 | 未计价 |
| Jev 0.65 | 702,103 | 35,105 | 未计价 |

原有路由器另有 **559,638 个 embedding 输入 token**，也因缺少 embedding 单价而未计价。报告没有缓存读取 token 的分项，所以费用按所有执行输入都采用普通输入价估算，没有使用缓存折扣；如果实际服务存在缓存读取，这些费用估算会偏高。上表每个成功任务均摊仅将该组 Qwen 费用除以成功任务数，不代表失败任务可以从实际账单中退款。

## 结果解释

- **成功率与卸载率呈反向趋势。** 原有路由器 SLM 占比最高（83.1%），成功率最低（50%）；Jev 从阈值 0.50 到 0.75，卸载率由 57.7% 降至 5.1%，成功率由 65% 升至 95%。这支持“在本批任务与当前提示词/模型下，更多卸载伴随更高失败率”的观察，但不能单凭 20 个任务推断一般因果规律。
- **Jev 0.75 是本批中值得继续验证的候选点，不是已证明优于原生的配置。** 它成功率与原生 LLM 并列 95%，SLM 卸载 15 次（5.1%），平均端到端时间增加约 12.7%，合计已知输入 token 增加约 17.2%。按给定价格，它的 Qwen 执行费用低约 4.0%，但尚未计 Jev 服务费用；加入 Jev 费用后，完整账单是否更低目前未知。
- **Jev 0.70 的卸载明显多于 0.75，但多 1 个任务失败。** 成功率 90%，卸载率 10.4%；端到端时延比原生约高 14.7%。
- **Jev 0.65/0.50 尚未达到原生质量。** 成功率分别为 80%/65%，且卸载率较高；这批结果不支持把它们作为当前默认阈值。
- **原有路由器表现较差。** 10/20 成功；20 个任务中 427 次实际模型调用，SLM 占 83.1%。另有 embedding 输入 559,638 token。
- **原生 LLM 仍是本轮质量和时延基准。** 19/20 成功，平均端到端 77.78 秒/任务；按给定价格，Qwen 执行模型估算费用为 $1.4497/20任务。Jev 0.75 虽然 Qwen 执行费用估算略低，但还要加上未计价的 Jev 路由费用，且时延更高。

## 数据质量与限制

- 报告标记 `complete=true`、`holdout_evaluation=true`，每组 20 个任务、调用消耗记录完整，`invalid_measurement_tasks=0`。
- 六组都出现一个或多个 AppWorld evaluation failure；失败数依次为 native 1、legacy 10、Jev 0.50 7、0.65 4、0.70 2、0.75 1。报告将其记为 `evaluation_failed`。
- 原始汇总报告中的成本金额字段全为 `null`。本报告新增的 Qwen 费用是根据用户提供的单价和逐模型输入/输出 token 计算的估算，并非服务端账单。Jev 与 embedding 服务价格、缓存读取 token 分项、硬件资源成本均未提供，故完整总成本仍无法确认。
- 端到端时间按 20 个任务耗时求均值；这是任务级平均，不等同于 Slurm 作业墙钟时长或六组串行运行总时长。
- 本轮样本量为 20 个 holdout 任务，能用于方向性比较，但阈值间差异可能受个别任务影响。

## 建议

1. 若继续验证 Jev，可优先观察 **0.75**，同时保留原生 LLM 作为质量对照。当前它与原生成功率持平，但更慢；按 Qwen 费率算出的 token 执行费用略低，是否能覆盖 Jev 本身费用尚不清楚，因此不能据此称为总体更优。
2. 进一步分析六组的失败任务交集和具体评测断言，尤其是 Jev 0.50、0.65、0.70 相对原生新增的失败，确认是否集中于某类需要长上下文、精确参数或多步状态修改的操作。
3. 若要正式比较“成本”，在实验配置里为 LLM、SLM、Jev 和 embedding 定义明确的每百万输入/输出 token 价格，或记录各自 GPU 服务占用成本，再重算货币成本。
4. 由于每组只有 20 个任务，建议扩大独立 holdout 任务集，并报告置信区间；阈值选择应同时看成功率、卸载率、JeV token 开销和时延，而不只看卸载比例。
