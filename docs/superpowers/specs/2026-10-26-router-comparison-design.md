# 四组路由开发实验

按用户已确认的方案实现并自动在服务器验收、执行：固定 20 个开发任务，比较原生全 LLM、旧双分类器、Jev context 阈值 0.8 和 0.7。任务名单沿用固定 Span 实验的 20 个任务，属于探索性开发数据，不作独立测试成绩。

模型、解码、40 步上限、Agent 提示词及 M4 关闭保持一致。旧路由使用原权重阈值，必须有真实 qwen3-embedding:0.6b 向量，拒绝 miss_no_vector 的退化对照。Jev 不改提示词和输入裁剪规则。每任务四组循环换序，串行运行；每格使用独立子进程、AppWorld 实验名、输出目录，避免全局状态串扰。

先独立运行任务 099174d_1 的四组作为技术验收，任务评分失败不阻止批跑；必须有实际模型派发，旧路由 hits>0 且 miss=0，Jev 有成功响应且审计完整。通过后执行 20×4，保留失败，不自动补跑。子进程超时有独立失败类别；服务故障或路由计数不可用停止批跑并保存剩余清单。

原路由还依赖 Ollama embedding，当前服务器缺失。先用 CPU 作业下载固定版本 Ollama 和官方 qwen3-embedding:0.6b，校验模型 blob 哈希，再验收服务 1024 维输出。GPU 作业只加载 Jev 和 embedding；沿用已确认可用的 LLM 与现有 284851 SLM，不停止或修改现有服务。独立 GPU 作业有时间上限并在结束时关闭自己启动的服务。

产物包括每组配置、任务清单及官方划分、源代码/模型权重哈希、服务元数据、单任务验收、逐格结果/进度/日志、完整 Jev 审计及四组对照报告。报告使用实际派发，分列执行模型输入/输出 token、Jev 输入 token、embedding 用量、失败/回退/回滚及耗时；费用未知保持 null。原生组没有的守卫计数记为不适用。

验收覆盖配置隔离、顺序、质量失败继续、缺向量拒绝、未知计数拒绝、拒绝覆盖与配对结果统计。本地测试后服务器验收，再自动开始 80 格开发实验。共享推理服务可能受外部负载影响，固定 seed 不保证位级复现。
