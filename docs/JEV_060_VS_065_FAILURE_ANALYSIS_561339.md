# Jev 0.60 与 0.65：失败轨迹对照

数据来自完成的四阈值实验 `561339`，相同20个开发任务，context输入。仅分析已保存结果，不重新申请GPU，不修改路由、执行提示词、收尾、守卫或评测结果。

## 主要结论

0.60成功14/20，0.65成功12/20，相差2个任务；不能由此认定0.60稳定优于0.65。逐任务配对为：双方成功9个、双方失败3个、仅0.60成功5个、仅0.65成功3个。

阈值只保证在**完全相同的路由输入和概率**下，0.60接受的SLM候选包含0.65接受的候选。在线执行时，第一次模型选择改变后，生成代码、工具反馈、后续上下文与概率都会改变，实际执行的SLM步骤不再是固定集合的包含关系。LLM也可能走出更长或出错的路径。

本轮0.60实际SLM调用107次、LLM360次；0.65实际SLM94次、LLM353次。总量少不代表任务完成质量更好。

## 下一步

1. 将0.60/0.65视为本次小样本在线结果，不按单次成功率排序后直接宣布路由能力更强。
2. 如验证阈值效应，优先固定上述分歧前的上下文和环境，分别执行SLM/LLM分支，并按原有局部正确性定义评测。不能只依据语法/运行成功判断，也不能用最终评测私有数据作为在线输入。
3. 如比较完整任务收益，固定配置和任务，重复运行以观察波动，再用独立任务验证。保留原始失败，报告答案契约、业务语义、上下文超限、预算耗尽等类别。
4. 任何收尾提示词、输出限制或强制LLM规则若要改动，应作为单独变量和对照实验，不能在阈值实验中悄悄修补。
