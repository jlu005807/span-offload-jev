# Jev 首轮 90 任务实验及旧实现对照（2026-10-23）

本轮已完成：90 个任务成功 85 个，成功率 **94.44%**；实际 SLM 调用仅 **1/1837（0.0544%）**。系统接入和结果记录已验证，但尚未证明有效卸载或净节省。高成功率发生在几乎全部使用 LLM 的条件下，不能归因于 Jev 路由质量。

本报告保存在本地，实际计算在服务器进行。它是首轮摸底，不是三输入模式、阈值和旧路由的完整受控比较。

## 1. 实验条件与证据

- 清单：`experiments/instances-90.txt`，固定顺序、串行、1 轮；项目自定义 90 任务，并非官方单一 split，组成见 [DATA.md](DATA.md)。
- Agent：AppWorld `react_code`；每任务最多 40 步。
- Jev：OpenJev-1.7B，服务名 `wev-1.7b`，`active + combined`，阈值 0.8，M4 关闭。
- 路由：`P(SLM) >= 0.8` 才卸载；Jev 不可用直接 LLM，不调用旧双门控。
- 输入：最近最多 10 个历史单元、12000 字符保护；本地原生编码预检查状态上限 4096 tokens、分支上限 8192 tokens。
- LLM：Qwen3.8-27B，共享 `tanylang` 的 `192.168.10.25:8101` 服务；接口报告名称一致，但没有与原部署逐文件验证权重和服务参数相同。
- SLM：Qwen3.5-9B，`192.168.10.26:8800`；Jev 与 SLM 共用 A800 80GB。
- 解码配置：temperature=0、top_p=1、seed=42、max_output_tokens=8192。快照中的 `enable_thinking: false` 未经确认实际透传，不据此声称关闭思考。
- Jev 部署权重 revision：`7418ae8b6e3b6a6507a8a58729ae491cd1c732d9`；API 本身不提供可信权重证明，审计 `revision_verified=false` 保留。

## 3. Jev 覆盖率与概率

| 路由结果 | 次数 | 占全部 1837 次决策 |
|---|---:|---:|
| 成功获得 Jev 判断 | 1561 | **84.98%** |
| 输入不可用 | 269 | 14.64% |
| 已发请求但失败 | 7 | 0.38% |
| 总不可用 | 276 | **15.02%** |

共发送 1568 次请求，成功率 **99.55%**。不可用原因：268 次 `input_too_large`、1 次 `input_too_long`、6 次 `timeout`、1 次 `invalid_response`；没有预算耗尽记录。输入超长主要卡在项目字符限制，不能据此断言这些输入都超过模型 token 上限。

在 **1561 次成功判断**上按调用等权计算：

| 概率指标 | 值 |
|---|---:|
| 平均 P(LLM) | 47.94% |
| 平均 P(SLM) | 52.06% |
| P(SLM) 最小 / 最大 | 14.24% / 82.15% |
| P(SLM) >= 0.8 | 1 次 |

这说明“几乎不卸载”不等于“始终偏向 LLM”：多数分数没有达到严格阈值。选项概率未经校准，不等于真实局部正确率；不能直接把阈值降到均值来追求卸载数量。

### 实现区别

| 项目 | 学长原路由 | 本轮 Jev |
|---|---|---|
| 路由器 | add4 训练产物、双 Logit 门控 | OpenJev-1.7B 原生 choice 接口 |
| 判断依据 | 局部正确性 gate 与净节省 net 两个分数及各自阈值 | 一次问题的 P(SLM) 与 0.8 阈值 |
| 输入处理 | 原有特征、嵌入和预处理 | 上下文＋代码提取的四特征文本/数值 |
| 额外资源 | 本地预测器，相关嵌入链路另计 | 额外 Jev 推理；本轮与 SLM 同卡 |
| 安全执行 | M3 守卫、按需回滚与 fallback | 复用 M3，未替换安全执行机制 |
| M4 | active 关闭，m4-on 单列 | 关闭 |

单个 P(SLM) 不等价于原来的“质量＋经济性”双门控，所以不能只对齐一个阈值就认定优化目标相同。

### 能得出什么，不能得出什么

- 数值上，本轮比旧第一轮 native-large 高 4.44 个百分点，比旧第二轮 active 高 18.84 个百分点；但本轮几乎全用 LLM，旧 active 约 19.5% 调用交给 SLM。不能称为同等卸载下的质量提升。
- 虽然清单相同，本轮串行、旧实验 4 并发；LLM 使用他人共享端点，权重版本及服务参数未完全核验，SLM/Jev 又同卡。模型耗时较低不构成 Jev 加速证据。
- 没有同期纯 LLM 和旧 active 对照，只有 1 轮，且首个测试任务曾用于接入调试；应定位为探索性实验，不能作为未经调试的独立测试结论。
- 只有一次 SLM 调用，无法评价有代表性的局部正确率、卸载后失败风险或 M3 的保护收益。单任务和故障注入验收不混入本轮质量结果。
- 未获得完整 Span 分支标签/统一价格模型，局部正确性、净节省、统计显著性均未证明。仅凭平均概率不能推断降低阈值后的任务成功率。
